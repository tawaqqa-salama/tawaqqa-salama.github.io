## الباب ١ — مقدمة

### ١.١ الهدف

تهدف قاعدة المعرفة الهندسية (EKB) إلى توحيد المرجعية الفنية لمنصة توقع في مجال استشارات السلامة والوقاية من الحريق داخل المملكة العربية السعودية، بحيث:

- تُغذي **محرك الامتثال** بمراجع الأكواد والأنشطة والمتطلبات النظامية.
- تُغذي **محرك القرارات** بسيناريوهات، مخاطر، وقرارات هندسية موثّقة.
- تُمكّن **المهندسين** من الرجوع السريع للأنشطة، الأنظمة، الحسابات، والتفاصيل التنفيذية.
- تُوفّر لمساعد **الذكاء الاصطناعي** مصادر استرجاع عربية موثوقة دون استبدال الاعتماد البشري.

EKB **ليست** مواصفة برمجية ولا تتضمن خوارزميات تنفيذ أو قواعد كود قابلة للتشغيل؛ هي مكتبة معرفية فقط.

### ١.٢ النطاق

**داخل النطاق:**

- أكواد ومعايير (محلية ودولية مرجعية).
- أنشطة وأنواع مبانٍ وإشغالات.
- مواد خطرة وأنظمة إطفاء وإنذار ومعدات.
- حسابات هندسية وتفاصيل تنفيذية ونماذج تقارير.
- FAQ وأخطاء شائعة ودروس مستفادة ورسومات مرجعية ومنتجات معتمدة (أمثلة).
- قرارات هندسية وسيناريوهات ومخاطر ومعرفة مؤسسية.

**خارج النطاق:**

- كود تنفيذي، مخططات قاعدة البيانات التفصيلية (انظر DDS)، واجهات API، سياسات أمن المعلومات التشغيلية، تسعير تجاري تفصيلي.

### ١.٣ طريقة الاستخدام

| المستخدم | طريقة الاستخدام |
|----------|------------------|
| محرك الامتثال | يقرأ مراجع الأكواد والأنشطة والمتطلبات الإلزامية/الاختيارية/المحظورة، ويربطها بـ `compliance_rules`. |
| محرك القرارات | يستدعي السيناريوهات والمخاطر والقرارات الهندسية لاقتراح مسار تصميم أو استثناء موثّق. |
| المهندسون | مرجع يومي للتصميم، المراجعة، الزيارات الميدانية، وإعداد التقارير. |
| الذكاء الاصطناعي | استرجاع مقالات ووسوم من `knowledge_articles` المرتبطة بمحتوى EKB؛ أي اقتراح يتطلب اعتماداً بشرياً. |

### ١.٤ إدارة الإصدارات

| القاعدة | التفصيل |
|---------|---------|
| ترقيم الوثيقة | SemVer مبسّط: رئيسي.فرعي (هذا الإصدار ١.٠). |
| تغيير رئيسي | إضافة باب، أو تغيير جوهري في متطلبات إلزامية. |
| تغيير فرعي | تصحيحات، أمثلة إضافية، تحديث تواريخ سريان. |
| الحالة | مسودة → قيد المراجعة → معتمد → مُلغى. |
| الأثر على المنصة | أي تحديث يُسجَّل في الباب ١٨ ويُنعكس على جداول المعرفة/الامتثال حسب ملحق أ. |

### ١.٥ المراجع

- كود البناء السعودي (SBC) — الأجزاء ذات الصلة بالسلامة من الحريق.
- متطلبات الجهات المختصة المحلية (الدفاع المدني / الجهات ذات العلاقة).
- NFPA (مرجع دولي مقارن عند غياب نص محلي أو كمكمل معتمد).
- UL / FM / SASO لاعتماد المنتجات والشهادات.
- وثيقة DDS v1.0 لمنصة توقع.
- تعاميم وتعليمات منشورة من الجهات المختصة (تُحدَّث في الباب ١٨).

### ١.٦ المصطلحات

| المصطلح | التعريف |
|---------|---------|
| EKB | قاعدة المعرفة الهندسية — هذه الوثيقة ومكتباتها. |
| DDS | مواصفة تصميم قاعدة البيانات للمنصة. |
| نشاط | تصنيف استخدام المنشأة لأغراض السلامة والامتثال. |
| إشغال | فئة استخدام الفراغات وحمل الأشخاص والمخاطر المرتبطة. |
| نظام إطفاء | نظام ثابت أو شبه ثابت لإخماد أو السيطرة على الحريق. |
| نظام إنذار | كشف وإشعار وإشارة إنذار حريق. |
| طلب هيدروليكي | التدفق والضغط المطلوبين عند نقطة التصميم. |
| استثناء | انحراف موثّق عن قاعدة امتثال بشرط السماح والاعتماد. |
| جهة مختصة | جهة رسمية ذات صلاحية اعتماد أو تفتيش سلامة. |

ملف المصطلحات الموسّع: [libraries/corporate-knowledge.md](./libraries/corporate-knowledge.md).

## الباب ١٣ — الأسئلة الشائعة (FAQ)

الملف: [libraries/faq.md](./libraries/faq.md).

1. **هل الرشاشات إلزامية في كل مبنى تجاري؟** — لا؛ تعتمد على المساحة والارتفاع والاستخدام ومتطلبات SBC/الجهة المختصة.
2. **متى يُستخدم Clean Agent بدل الماء؟** — عند حماية أصول حساسة للماء (مراكز بيانات، غرف تحكم) مع إحكام الغرفة وتصميم معتمد.
3. **هل NFPA يغني عن SBC؟** — لا؛ SBC والجهة المختصة مقدَّمان؛ NFPA مرجع مكمل عند الاعتماد.
4. **ما الحد الأدنى لطفايات المبنى؟** — حسب نوع الخطر ومسافات التغطية والكود المحلي؛ يُحدَّد في التقرير الفني.
5. **هل مركز البيانات يحتاج رشاشات؟** — غالباً كشف مبكر + إطفاء نظيف أو pre-action؛ القرار حسب تقييم المخاطر والجهة.
6. **ماذا لو تعارضت مواصفة منتج مع الكود؟** — يُقدَّم الكود؛ يُستبدل المنتج أو يُوثَّق استثناء إن سُمح.
7. **متى تُطلب الرغوة في المستودع؟** — عند تخزين سوائل قابلة للاشتعال بكميات/ترتيبات تستدعي ذلك.
8. **هل يمكن قفل مخرج الطوارئ؟** — لا أثناء الإشغال؛ آليات خروج آمنة فقط حسب الكود.
9. **ما مدة احتياطي ماء الحريق؟** — حسب تصنيف الخطر والكود/المواصفة المعتمدة للمشروع.
10. **هل تقرير الذكاء الاصطناعي كافٍ للاعتماد؟** — لا؛ يلزم اعتماد مهندس وربط بوثيقة رسمية.
11. **كيف تُحدَّث قاعدة المعرفة؟** — عبر الباب ١٨ ومراجعة إصدار EKB وربط `knowledge_articles`.
12. **ما الفرق بين إنذار تقليدي وعنونة؟** — العنونة تحدد موقع الجهاز بدقة أعلى وتُفضَّل للمباني الكبيرة والمعقدة.

4. تقييم المخاطر (مكتبة المخاطر).
5. اختيار الحل وتوثيق المبررات والمراجع.
6. إن لزم: مسار استثناء مع بدائل سلامة معادلة.

أمثلة قرارات: اختيار pre-action لمركز بيانات؛ إضافة رغوة لسوائل في مستودع؛ رفع كثافة الرش بعد تغيير ارتفاع التخزين.

## ملحق أ — العلاقة مع DDS

المصدر: [docs/dds](../dds/).

| مكوّن EKB | جدول/كيان DDS | العلاقة |
|-----------|---------------|---------|
| مقالات معرفة، FAQ، دروس | `knowledge_articles` | `article_code`, `question`, `explanation`, `tags`, … |
| متطلبات أكواد وأنشطة | `compliance_rules` | `rule_code`, `reference_code`, `system_category`, `rule_body` |
| أنشطة | `ref_activity_types` | رموز مثل `ACT-COMM` |
| أنواع مباني | `ref_building_types` | تصنيف المباني |
| مصنّعون/منتجات | `ref_manufacturers` (+ معدات) | أمثلة الباب ١٧ |
| وحدات قياس | `ref_units` | ل/د، بار، م² |
| استثناءات | `compliance_exceptions` | قرارات انحراف موثّقة |
| وثائق وتقارير | `documents` / مرفقات | قوالب الباب ١٢ |

EKB يُعرّف **المعنى والمحتوى المرجعي**؛ DDS يُعرّف **التخزين والعلاقات والحقول**. لا يُستبدل أحدهما بالآخر.
