# مكتبة التحديثات (Updates Log)

**الغرض:** سجل تغييرات الأكواد والجهات والمواصفات والقوالب وأثرها على معرفة المنصة وقواعد الامتثال.  
**الربط:** [EKB الباب ١٨](../EKB-v1.0.md) · مراجعة `compliance_rules` و`knowledge_articles`.

---

## قالب إدخال تحديث

| الحقل | الوصف |
|-------|--------|
| `update_id` | UPD-YYYY-NNN |
| التاريخ | تاريخ الإدراج في EKB |
| نوع التحديث | كود / جهة مختصة / مواصفة / منتج / قالب / درس مستفاد / إصدار EKB |
| المرجع الخارجي | رقم تعميم، طبعة كود، … |
| ملخص التغيير | ماذا تغيّر؟ |
| الأثر على النظام | قواعد امتثال، أنشطة، قوالب، منتجات، قرارات |
| إجراء مطلوب | من يفعل ماذا قبل تاريخ |
| الحالة | مفتوح / قيد التطبيق / مُغلق |
| إصدار EKB الناتج | إن وُجد |

## إدخالات احتياطية (تُفعَّل عند حدوثها)

| النوع المتوقع | مثال أثر |
|---------------|----------|
| تحديث طبعة SBC | مراجعة كل القواعد ذات `reference_code` يبدأ بـ SBC- |
| تعميم جهة مختصة لمحطات الوقود | تحديث `ACT-FUEL` وسيناريو المحطة وقواعد `CA-CD-FUEL-*` |
| سحب شهادة منتج | إيقاف `product_id` في قائمة المعتمد وإخطار المشاريع المفتوحة |
| تحديث مواصفة طفايات SASO | مراجعة عروض التوريد وبند المعاينة |
| تغيير قالب شهادة الإنجاز | إصدار قالب جديد دون حذف القديم المعتمدة |

## مسار تطبيق تحديث على الامتثال

1. تسجيل `update_id` هنا.  
2. تحديد القواعد المتأثرة في `compliance_rules` (إصدار جديد للقواعد لا تعديل صامت).  
3. تحديث مقالات المعرفة والوسوم.  
4. إبلاغ المهندسين بالمشاريع المفتوحة ذات الصلة.  
5. إغلاق التحديث عند اكتمال التطبيق أو توثيق الاستثناء الزمني.
