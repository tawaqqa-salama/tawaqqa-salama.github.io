# مكتبة المعرفة المؤسسية

**الغرض:** سياسات وممارسات مؤسسية تضمن استخدام EKB بجودة متسقة داخل منصة توقع، دون تحويل الوثيقة إلى كود تشغيلي.  
**الربط:** الجودة الفنية · الصلاحيات · الذكاء الاصطناعي · [EKB الباب ١](../EKB-v1.0.md).

---

## ١. سياسة الجودة الفنية

| المبدأ | التطبيق |
|--------|---------|
| مرجعية واحدة | EKB + DDS + أكواد المشروع المعتمدة |
| إثبات | كل توصية فنية مربوطة بمرجع (كود/حساب/معاينة) |
| مراجعة النظير | إلزامية للتقارير الفنية للمشاريع عالية الخطر (مستشفيات، وقود، كيماويات، بيانات) |
| لا اختصار على السلامة | ضغط الجدول لا يبرر حذف اختبارات القبول |
| تحسين مستمر | دروس مستفادة → تحديث EKB عبر updates-log |

---

## ٢. مصفوفة صلاحيات الاعتماد الهندسي (إطار)

| نوع المخرج | يعدّ | يراجع | يعتمد |
|------------|------|--------|--------|
| ملاحظة زيارة روتينية | مهندس/فني | مشرف | — |
| تقرير فني متوسط الخطر | مهندس | مهندس أول | مدير فني |
| تقرير عالي الخطر / استثناء امتثال | مهندس أول | مدير فني | مخوّل امتثال + مدير فني |
| شهادة إنجاز | مهندس مشروع | مدير فني | مخوّل تعاقدي |
| إدراج منتج في قائمة المعتمد | مهندس مواصفات | مدير فني | لجنة فنية مختصرة |
| تحديث باب في EKB | محرر معرفة | مراجع فني | اعتماد إصدار |

---

## ٣. مسار مراجعة التقارير

1. إعداد المسودة وفق قالب الباب ١٢.  
2. فحص قائمة تحقق الأخطاء الشائعة.  
3. مراجعة نظير (إن لزم حسب الخطر).  
4. اعتماد وإصدار `version_label`.  
5. تسليم للعميل/الجهة مع حفظ النسخة المعتمدة.  
6. أي تعديل لاحق = إصدار جديد.

## ٤. قواعد أرشفة المعرفة

| البند | القاعدة |
|--------|---------|
| مدة الاحتفاظ | توافق سياسة أرشفة المنصة (راجع DDS — غالباً سنوات متعددة) |
| الإصدارات | لا حذف للإصدارات المعتمدة من EKB أو التقارير |
| السرية | تخفيف بيانات العملاء في الدروس المستفادة العامة |
| الفهرسة | وسوم عربية موحّدة: نشاط، نظام، خطر، مرحلة |
| اللغة | العربية أساس؛ الرموز الإنجليزية مسموحة للمعايير والمعدات |

## ٥. قاموس مصطلحات موسّع (مختارات)

| المصطلح | التعريف المؤسسي |
|---------|------------------|
| نقطة الطلب (Demand) | تدفق وضغط مطلوبان عند مصدر النظام لنطاق التصميم |
| Pre-action | نظام رشاشات يتطلب حدث كشف قبل امتلاء الأنابيب بالماء (حسب النوع) |
| ESFR | رشاشات استجابة سريعة مبكرة الإخماد لتطبيقات تخزين معينة |
| مقصورة دخان | منطقة معمارية/إنشائية للحد من انتقال الدخان |
| إخلاء أفقي | نقل شاغلين إلى منطقة ملاجئة بنفس المستوى دون النزول فوراً |
| Listing | إدراج منتج في قائمة جهة اعتماد (UL/FM…) لطراز محدد |
| استثناء امتثال | انحراف موثّق عن قاعدة مع بديل سلامة معادل عند السماح |
| As-built | مخطط يطابق التنفيذ الفعلي بعد التغييرات |
| عمل ساخن | لحام/قطع/جلخ يتطلب تصريحاً وضوابط حريق |
| طبقة حماية متعددة | جمع كشف مبكر + إطفاء + إجراءات تشغيل للأصول الحرجة |

## ٦. ضوابط استخدام الذكاء الاصطناعي

| القاعدة | التفصيل |
|---------|---------|
| الدور | اقتراح وصياغة ومساعدة بحث في EKB فقط |
| غير مسموح | اعتماد نهائي، تجاوز كود، إنشاء استثناء وهمي، تعديل قواعد امتثال دون بشر |
| الإفصاح | يُشار عند استخدام AI في إعداد مسودة إن طلبت سياسة الشركة |
| التحقق | مهندس يتحقق من كل رقم وحساب ومرجع قبل الاعتماد |
| التغذية الراجعة | تقييم الاقتراحات يغذي تحسين المقالات لا الاعتماد الآلي |
| الخصوصية | لا تُدخل بيانات عميل حساسة في أدوات غير معتمدة من المنصة |

## ٧. علاقة الفرق بـ EKB

| الفريق | الالتزام |
|--------|----------|
| هندسة | المرجع اليومي للتصميم والمراجعة |
| مشاريع ميدانية | قوائم تحقق التنفيذ والزيارات |
| جودة/امتثال | تحديث القواعد والدروس |
| مبيعات فنية | حدود النطاق والافتراضات في العروض |
| منتج المنصة | ربط المحتوى بجداول المعرفة دون تغيير معنى EKB |

## ٨. مؤشرات صحة المعرفة (KPIs إطارية)

| المؤشر | هدف إرشادي |
|--------|-------------|
| نسبة التقارير المعتمدة التي تذكر طبعة الكود | → 100% |
| زمن إغلاق تحديث حرج في updates-log | حسب خطورة التعميم |
| تكرار نفس خطأ DOC/EXE بعد درس معتمد | يتناقص |
| مقالات معرفة دون وسوم | صفر |
